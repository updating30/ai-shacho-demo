制作事例 ／ AIエージェント

AIが社長として、
副業の受注業務を回す。

案件選び、応募文の下書き、返信の準備、受注後の要件整理、納品物の準備。開発以外の業務を、Claude Code で動く「AI社長」に任せ、毎週の業務として実際に回しています。 ただし、どの案件に応募するかを決めるのも、送るのも人です。AIに任せる範囲と人が判断するところを分ける、「業務をAIに任せる仕組み」の一例です。

背景

開発の時間は、開発に使いたい。

本業を持ちながらの副業は、使える時間が週10〜20時間ほどです。その中で、受注にまつわる周辺の業務が思った以上に時間を取っていました。

案件を選ぶのに時間がかかる

募集は週に100件以上。受けられるか・割に合うかを1件ずつ読んで判断するだけで、平日の夜が終わってしまう。

判断の基準がぶれる

疲れていると条件の悪い案件にも手を出したくなる。応募するかどうかの線引きが、日によって変わってしまう。

書類仕事が開発を圧迫する

応募文、要件の確認、使い方の説明書、納品のメッセージ。どれも大事だが、毎回ゼロから書くと重い。

しくみ

AIが準備し、人が決める。
その繰り返しで、受注から納品まで進む。

AI社長は判断材料をつくる役、オーナー（人）は決める役です。外部への送信が発生する手前では、AIは必ず止まって指示を待ちます。

AI社長が行う オーナーの決裁（AIはここで止まる）
  1. AI

    AI社長/weekly

    今週の案件を採点して、一覧で示す

    公開されている案件情報を、明文化した選定基準で100点満点に採点。基準を満たす案件を最大10件、推す理由・懸念点・競争の激しさ（倍率）を添えて一覧にします。応募文はまだ書きません。

  2. 決
    裁

    オーナー

    応募文を書く案件を、番号で選ぶ

  3. AI

    AI社長/apply

    選ばれた案件だけ、応募文を下書きする

    書く前に、クライアントの困りごと・納品後に業務がどう変わるかを整理したメモを残し、そのうえで下書きします。選ばれていない案件の下書きはつくりません。

  4. 決
    裁

    オーナー

    内容を確かめて、自分の言葉に直し、自分で応募する

  5. AI

    AI社長/reply

    返信が届いたら、返事の案をつくる

    相手の質問に答える案と、こちらから確かめたいことを整理します。外部の連絡先へ誘導されたときは、サービス上で続けたいと伝える案にします。

  6. 決
    裁

    オーナー

    確かめて、自分で送る

  7. 決
    裁

    オーナー

    「受注した」とAIに伝える

    この一言があるまで、AIは開発に着手しません。

  8. AI

    AI社長/kickoff

    要件を整理し、確認事項を下書きする

    目的・機能・受け入れ条件・範囲外を要件書にまとめ、足りない点をクライアントが答えやすい選択式の質問にします。

  9. 決
    裁

    オーナー

    確認事項をクライアントへ送り、回答を持ち帰る

  10. AI

    AI社長/deliver

    開発・検証し、納品物をそろえる

    受け入れ条件を1つずつ実際に動かして確認。ソース、非エンジニア向けの使い方、設定の雛形、納品メッセージ案を準備します。

  11. 決
    裁

    オーナー

    確認して、納品する

業務の呼び出し方

普段の言葉で頼めば、決まった手順で動く。

業務ごとに手順書（カスタムコマンド）を6種類用意しました。毎回同じ品質で、抜け漏れなく進みます。

/weekly「今週の案件を出して」

週次の案件提案

  • 案件情報を集めるツールを動かす前に、所要時間と費用を示して許可を取る
  • 足切り → 採点の順で評価し、上位は案件ページの本文まで読む
  • 応募が殺到している案件は、倍率に応じて減点・足切り
  • 一覧を示して止まる。応募文は、選ばれた案件だけ
運用中
/apply「1番と3番で応募文を書いて」

応募文の下書き

  • 主語はクライアント。技術を並べるのではなく、業務がどう良くなるかを中心に
  • 依頼の理解 → 価値 → 方法 → 実績 → 進め方 → 見積案 → 質問 の構成
  • 実績を盛らない・外部の連絡先を書かない
運用中
/reply「◯◯でメッセージが来た」

返信の下書き

  • 相手の質問への答えと、こちらから確かめたいことを整理
  • 外部の連絡先へ誘導されたら、サービス上で続けたいと丁寧に伝える
運用中
/status「今どうなってる？」

今の状態の確認

  • 締切が近い案件と、オーナーの判断待ちを先に示す
  • 締切を過ぎた案件は「期限切れ」に片付ける
運用中
/kickoff「◯◯を受注した」

受注後の要件整理

  • 目的・機能（必須／あれば良い）・入出力・動作環境・受け入れ条件を整理
  • 要件の穴を、選択式や具体例つきの質問にして下書き
実装済み・初受注から稼働
/deliver「◯◯の納品準備をして」

検証と納品物の準備

  • 受け入れ条件をすべて実際に動かし、結果を検証記録に残す
  • 秘密情報・クライアントのデータが混ざっていないか最終チェック
実装済み・初受注から稼働

設計の要点

任せられるAIにするために、決めたこと。

AIに業務を任せるときに大事なのは、賢さよりも「どこまで任せ、何を基準に判断させるか」だと考えています。

外部への送信は、すべて人が行う

応募・メッセージ・納品・見積の確定は、AIの権限の外に置きました。AIが止まる場所を5か所に決め、指示があるまで先へ進みません。

判断の基準を、文書で渡す

強み・稼働条件・受けない案件を 事業定義.md、採点の配点を 選定基準.md に明文化。AIの判断に一貫性が出て、理由も説明できます。

水増しをしない

提案ラインに届く案件が無い週は「今週は適切な案件なし」と報告します。10件そろえることより、判断材料として正直であることを優先しました。

競争の激しさも、判断に入れる

強みに合っていても、応募が殺到している案件は受注の見込みがほとんどありません。倍率（応募数 ÷ 残り枠）で減点し、100倍以上は足切りにしました。応募文を書く手間を、勝ち目のある案件に回すためです。

状態の記録は、1か所だけ

全案件の状態（提案 → 応募済 → 受注 → 納品済）は 台帳.md だけが持ちます。提案済みの案件は次週の候補から自動で外れます。

既存のツールには、読み取りだけで連携

以前に作った、案件情報を整理するツールは改変せず、データベースを読み取り専用で開く小さなスクリプトを挟みました。既存の仕組みを壊さずに機能を足す形です。

規約とお客様のデータを守る

規約上グレーな依頼は採点前に足切り。クライアントから預かったデータやAPIキーは、案件フォルダの外へ出さないことを社長の規則にしています。

構成と技術

フォルダ1つで完結する会社。

規則・方針・手順・記録をすべてテキストファイルで持つので、中身を誰でも読めて、直すのも簡単です。

AI社長/
├─ CLAUDE.md       会社の憲法（役割・止まる場所）
├─ 台帳.md         全案件の状態（唯一の記録）
├─ 会社方針/
│   ├─ 事業定義.md  強み・稼働条件・受けない案件
│   └─ 選定基準.md  採点の配点と提案ライン
├─ 週次提案/        週ごとの提案（2026-W41.md …）
├─ 案件/<案件ID>/   1案件1フォルダ
│   ├─ 応募文.md
│   ├─ 要件.md ／ 確認事項.md
│   ├─ src/        開発したツール
│   └─ 納品/        納品物一式
├─ tools/
│   └─ candidates.py DBを読み取り専用で参照
└─ .claude/commands/ 業務の手順書 6種
  • AIエージェントClaude Code（CLAUDE.md による行動規範、カスタムスラッシュコマンド）
  • データ連携Python ／ SQLite（読み取り専用の接続）／ JSON
  • 案件情報の整理公開されている案件情報を整理する自作ツール（Python・Claude API による一次評価）
  • 記録と方針Markdown（台帳・事業定義・選定基準・週次提案）
  • 開発する側Python ／ Streamlit ／ Claude API ／ pandas ほか、案件に応じて

ご提供できること

同じ型で、御社の業務もAIに任せられます。

「AIが準備し、人が決める」「判断の基準を文書で渡す」という型は、受注業務に限らず使えます。たとえば、こんな形です。

問い合わせメールの一次対応

AIが行う
重要度と担当部署で仕分け、返信の下書きをつくる
人が行う
下書きを確認して送信する

経費・請求書の処理

AIが行う
決まったルールで判定し、迷うものだけ候補を並べる
人が行う
候補を承認したものだけ登録する

社内の質問への回答

AIが行う
社内文書を検索し、根拠の文書を示して回答する
人が行う
根拠を見て、回答を使うか判断する

業務の「どこまでAIに任せるか」から、一緒に考えます。

要件がまだ曖昧な段階でも大丈夫です。今の業務の流れを伺い、AIに任せる部分と人が判断する部分の線引きからご提案します。
